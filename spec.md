# StaticHub Web — Specification

## Purpose and Audience

The StaticHub public website (`statichub-web`) is a static web application deployed on Netlify.
Its audience is developers evaluating packages available through the StaticHub ecosystem.
It allows visitors to browse all available packages, read their metadata, and copy install commands.

## Data Sources

### Package metadata

Package metadata originates from `meta.yaml` files in the `statichub-pkg` repository.
A GitHub Action in `statichub-pkg` generates a `staticweb.json` file aggregating all package
metadata and pushes it into this repository. The website consumes `staticweb.json` client-side
via JavaScript; no server-side rendering or runtime API call is required.

### Star counts

Star counts are stored in a `stars.json` build artifact. This file is generated by a scheduled
CI job (see [CI Pipeline](#ci-pipeline)) and consumed at build time. It is not stored in
`staticweb.json` or any other package schema file.

## `stars.json` Schema

`stars.json` is a JSON object keyed by `{platform}/{owner}/{repo}` and valued by integer star count.

Example:

```json
{
  "github/gchq/CyberChef": 28000,
  "gitlab/inkscape/inkscape": 4100
}
```

Key format rules:

- `platform` is either `github` or `gitlab` (lowercase).
- `owner` and `repo` are taken directly from the repository path (case-preserved).
- Keys are unique across platforms because the platform prefix disambiguates them.

Packages with no GitHub or GitLab source are silently omitted from `stars.json`.

## CI Pipeline

### Star count job

**Trigger:** daily schedule (e.g. `cron: '0 6 * * *'`), plus manual dispatch.

**Steps:**

1. Check out this repository and the `statichub-pkg` repository.
2. Iterate all `meta.yaml` files under `statichub-pkg/packages/`.
3. For each package, detect the upstream platform and repository identifier:
   - **GitHub:** `source.type == "github_release"` → use `source.repo` (format `owner/repo`).
     Also check `source.url` for `github.com` hostnames to cover `git` and `archive` types.
   - **GitLab:** `source.type == "gitlab_release"` → use `source.repo`.
     Also check `source.url` for `gitlab.com` hostnames.
4. For each detected GitHub repository, call
   `GET https://api.github.com/repos/{owner}/{repo}` with a `GITHUB_TOKEN` secret and read
   the `stargazers_count` integer field from the JSON response.
5. For each detected GitLab repository, call
   `GET https://gitlab.com/api/v4/projects/{namespace}%2F{name}` and read the `star_count`
   integer field.
6. Accumulate results into a `stars.json` object using the `{platform}/{owner}/{repo}` key format.
7. Write `stars.json` to the repository working tree and publish it as a build artifact
   (e.g. via `actions/upload-artifact`). The website build step downloads this artifact before
   building so it is available at build time.

**Error handling:** HTTP errors or missing fields for individual packages are logged and skipped;
they do not fail the job. Rate-limit responses (HTTP 429 / 403 with rate-limit headers) should
be retried once after the indicated wait period before being skipped.

## Pages

### Homepage

- Project overview and value proposition.
- CLI install instructions: `go install github.com/biolds/statichub-cli@latest`.
- Links to the `statichub-cli` and `statichub-pkg` GitHub repositories.

### Public catalog

- Lists all packages from `staticweb.json`.
- Displays per package: title, description, tags, version, and star badge (if available).
- Supports client-side full-text search across title, description, and tags.
- Supports client-side filtering by tag.

### Package detail page

- Displays all available metadata: title, description, homepage, live URL, tags, source type,
  source repository link, version.
- Shows a copyable install command: `statichub install {path}`.
- Shows the star badge when `stars.json` contains an entry for the package's upstream repository.

## Star Badge Component

The star badge:

- Displays a star icon (`★` or equivalent SVG) alongside the formatted star count
  (e.g. `12.4k` for 12 400).
- Links to the upstream repository URL (GitHub or GitLab).
- Is rendered only when a count is available in `stars.json`; it is silently omitted otherwise.
- Is a purely client-side, read-only UI element requiring no network call at render time.
